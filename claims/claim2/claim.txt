CLAIM 2 (Functional)

The same ANCHOR executable is schema-switchable across three different
ontology packages -- UCO, STIX, and MALOnt -- through a single --schema switch,
with no change to the extraction logic. UCO contains OWL and SHACL definitions;
the packaged STIX and MALOnt schemas are OWL-only. This substantiates the
paper's central design principle that the extraction pipeline is decoupled from
any specific ontology schema (Section IV-A, principle (i); Table I "Schema
dependency: Any OWL/SHACL").

Paper connection: Section IV-A System Overview; Table I.
Artifact components: artifact/ontology/{uco,stix,malont}/, the --schema flag in
artifact/main.py, artifact/src/nodes/mapper.py, artifact/src/nodes/exporter.py.

SCOPE NOTE. This is a FUNCTIONAL claim. It asserts that all three packaged
schemas load and drive the same executable to a structurally valid,
schema-aligned output. Claim 2 exercises schema switching; it does not claim
that the OWL-only STIX and MALOnt packages exercise SHACL validation. Claim 1's
UCO run exercises the SHACL-capable path. This claim does NOT assert the
per-schema accuracy numbers reported in the paper. The Results Reproduced badge
is NOT requested.

MODEL CAPABILITY CAVEAT

ANCHOR's ontology mapper drives the MCP server through multi-step tool calling,
so this claim depends on the chosen model sustaining several dependent tool calls
per entity and predicate. Intentional generic fallbacks remain valid when no
schema term fits. The claim check rejects operational fallbacks caused by a
timeout, exception, missing final tool call, or missing entity URI, and rejects
an all-generic graph. check_endpoint.py probes tool calling before the run;
claims/claim3 validates the package with no LLM at all.
